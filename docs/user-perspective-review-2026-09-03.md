# 全功能用户视角评审（2026-09-03）

> 评审性质：**完整产品走查**。与既有语料域评审（`docs/corpus-driven-writing/user-perspective-review-2026-09-02*.md`）不同，本轮从**新用户的第一印象**出发，覆盖书架、章节编辑、AI 对话、角色/地点/弧线/时间线/读者视角/偏好、技能、全局搜索、Git 历史、设置、帮助、个人中心、素材库与导入等全部功能面。
> 评审方式：以仓库自带的官方 mock bridge（`frontend/scripts/app-mock-workflow/mock-bridge.mjs`，与 Playwright 套件同源）驱动真实前端逐视图走查，逐屏核对 DOM/可访问性树并截图取证，关键结论回到源码复核（附 `file:line`）。数据为 mock 场景（6 章悬疑小说《全局回归小说》），真实后端行为未在本轮触发；凡属 mock 数据本身的问题均已注明，不做误报。
> 证据口径：每条结论要么来自走查中的可访问性树/截图，要么来自代码复核；行号以当前 `master` HEAD（`fc349da`）为基线。

## 一、总评

Novelist 目前处于「**功能成体系、打磨未收口**」的状态。从用户视角看，它已经是一个完整可用的 AI 长篇写作工作台：写作、对话、创作要素管理、素材库、Git 历史全链路都能跑通，且**没有发现数据丢失或流程死锁级的问题**（前四轮语料域评审已把这类问题基本收口）。但把它当作「没读过文档的新用户」来走查时，能稳定地撞到三类问题：

1. **术语与本地化不一致**：素材库的覆盖度地图、浏览页、材料化状态、读者视角侧栏、Git 历史、设置页里，大量原始英文枚举键（`sentence`、`continuity`、`queued`、`known`、`Release endpoint`、`Diff`/`Patch`）直接暴露给中文作者。作者能看懂流程，但会被这些「半中半英」的界面不断打断，且会怀疑某些值是 bug。
2. **几处「看起来像 bug」的真实 UI 缺陷**：书架卡片嵌套按钮、章节列表默认折叠、搜索后主区不变、`第{number}章 {title}` 模板原样显示、时间线「共 1 - 1 章」——这些不是崩溃级问题，但用户第一次遇到时会停下来怀疑自己的操作。
3. **无障碍细节欠账**：多处 icon-only 按钮无可访问名、hover 才可见的操作按钮对键盘用户不可见、原生 `confirm()` 与应用内对话框混用。

界面整体美观（浅色鼠尾草绿/奶油主题完整统一，深色主题同样自洽），信息密度与卡片风格一致，CRUD 视图模板统一——这部分可以打高分。

## 二、亮点（用户会喜欢的地方）

- **AI 对话的工具调用可视化**：工具事件以卡片形式呈现（读取章节列表/搜索完成），搜索词、来源链接、可折叠「搜索结果总结」一应俱全，作者对「AI 刚才做了什么」完全透明。
- **审批/逃生门机制**：审批卡片等待超 6 秒出现「结束本轮」、60 秒升级为「后端可能已失效」建议，作者永远不会被钉死在等待态。
- **章节删除的撤销**：删除前预读正文与大纲，撤销以新章号完整恢复内容，且动作通知常驻不自动消失——「手滑后悔」有完整的后悔药。
- **Git 历史**：提交列表分页、重命名/二进制标记、旧内容/新内容对照 + 原始 Patch + 「复制诊断」——对不熟 Git 的作者是友好的版本回溯入口。
- **素材库的状态可见性**：每本书的状态徽标（已导入/导入失败/语料抽取失败/插槽识别失败）、制作页的分步流程（章节切分→确认边界→批次材料化→候选复核）与漏斗统计，长任务可感知、可定位。
- **个人中心写作日历**：年度热力图 + 连续写作/累计字数统计，写作成就感可视化。
- **空状态与错误处理**：书架「还没有作品，创建第一部吧」、素材库「选择一个参考来源」、错误条带「重试/关闭 + 折叠诊断详情」、导入恢复横幅「复制诊断」——几乎每个面都有得体且可操作的兜底。
- **快捷键**：Ctrl+S 保存、Ctrl+Shift+V 预览切换挂在工作区层，切面板不失效。

## 三、问题清单

严重度：🔴 高（会造成误解/误操作或明显坏体验） · 🟠 中（一致性/可发现性） · 🟡 低（打磨细节）。

### A. 结构与逻辑

**A1 🔴 书架卡片存在「交互元素嵌套」**：整卡是 `div[role="button"]`（打开作品），内部又放了真实的 `<button>`（更换封面）（`BookshelfView.tsx:185-247`）。可访问性树里表现为 `button 打开作品` 内嵌 `button 更换封面`，HTML 语义非法——读屏无法确定焦点归属，键盘操作行为不稳定（走查中点击封面区域实际触发的是更换封面而非打开）。**改法**：把打开动作放到卡片标题/内容上的独立按钮，封面区与打开区分离。

**A2 🔴 hover 才可见的操作按钮对键盘用户隐形**：书架卡片的「导出/编辑/删除」与章节行的「编辑/删除」都用 `opacity-0 group-hover:opacity-100`（`BookshelfView.tsx:227-246`、`ChapterList.tsx:294-315`）。按钮仍是 Tab 焦点目标，但聚焦时容器不触发 group-hover，**键盘作者会 Tab 到看不见的按钮**。**改法**：容器增加 `group-focus-within:opacity-100`（或 `:focus-within`），让键盘聚焦同样显形。

**A3 🟠 章节列表默认折叠，写作主入口藏起来**：`expandedBlocks` 初始为空（`ChapterList.tsx:41`），6 章的小说也要先点开「第 1 - 6 章」折叠条才看得到章节目录；超过 100 章后还按 100 章分块、逐块展开。对以「点开某章继续写」为最高频操作的工作台，这个默认状态值得商榷。**建议**：首个分块默认展开（或记住上次展开状态并持久化）。

**A4 🟠 全局搜索的呈现位置令人困惑**：点活动栏「搜索」后，`handleActivitySelect('search')` 只 `setSidebarPanel('search')`（`WorkspaceView.tsx:262-265`），结果列表渲染在**左侧窄栏**，主内容区仍停留在上一个视图（走查中停在「个人中心」）。作者输入关键词时，眼睛看到的是旁边一个无关的旧页面，结果被挤在约 220–340px 的窄栏里。**建议**：进入搜索时把主区切换为「搜索结果」视图（或至少清空/弱化旧视图），让结果占主区宽度。

**A5 🟠 章节删除确认用原生 `window.confirm`**（`ChapterList.tsx:131`），而小说删除/导入/归档等都有应用内样式化对话框——同一产品里确认体验两套，原生弹窗与主题完全不搭。**建议**：章节删除也换成应用内确认对话框（顺带统一「撤销」入口的文案）。

**A6 🟡 两处重复入口**：活动栏「设置」与顶栏齿轮打开同一个对话框（`WorkspaceView.tsx:252` 与 `:488` 均 `setShowSettings(true)`）；书架侧栏与主工具栏各有一个「新建作品」。不致命，但新用户会困惑「为什么有两处」。

**A7 🟡 帮助文档与真实导航脱节**：帮助「快速入门」描述左侧活动栏为「搜索、小说、章节、偏好、角色、地点、故事弧线、时间线、读者视角、技能」，而实际顺序是「书架、素材库、设置、章节、搜索、技能、角色、地点、弧线、时间线、读者视角、偏好、Git 历史」，且漏掉了素材库、Git 历史与设置入口。首次进应用就弹帮助的新用户按图索骥会对不上号。**建议**：帮助文案改为按实际活动栏逐项生成，或直接引用同一份配置。

### B. 文案与本地化

**B1 🔴 素材库全量暴露英文枚举**：覆盖度地图直接把 `material_type`/`sentence`/`passage`/`continuity`/`emotion_evidence`/`rain_threshold`/`close` 等原始键渲染给中文用户（`CorpusAreaView.tsx:158-167`）；浏览页卡片展示 `feature_family · feature_key`、`review_state`（`unverified/low_confidence/confirmed/rejected`）、`technique_family`（`CorpusAreaView.tsx:276-282, 360-368`）。这是素材库最重要的「看懂我的语料」界面，却全是英文学术黑话。**建议**：为 taxonomy 键建一张中文映射表（参考 `referenceAnchorStates.ts` 的做法），覆盖度地图/浏览页/候选标签统一走映射，未映射键再回退原文。

**B2 🟠 同一概念中英混排**：读者视角侧栏显示英文类型 `known`，主卡片却显示中文「已知」（`ReaderView.tsx:19-31`）；材料化状态显示「运行 queued」「状态：running」（`ReferenceCorpusWorkspace.tsx:704-712` 只做了 `replaceAll('_',' ')`）；Git 历史中「Diff」「Patch」「binary」「重命名」并存；设置页「Release endpoint」标签（`GeneralConfigTab.tsx:522`）。**建议**：状态/枚举统一走 `stageLabel`/映射函数这类本地化层，术语表沉淀到一处。

**B3 🟠 分隔模板原样显示，像未渲染的 bug**：素材库制作页在章节切分卡片里把 `第{number}章 {title}` 直接印出来（`ReferenceCorpusWorkspace.tsx:671`）。对不了解「分隔模板」概念的用户，这就是一串带花括号的乱码。**建议**：加前缀标签（如「分隔模板：」）+ 等宽字体 + 一行说明「{number} 表示章号、{title} 表示标题」。

**B4 🟡 时间线标题「第 1 - 26 章 · 共 1 - 1 章」难读**（`TimelineView.tsx:542`）：前半是视图窗口轴（固定 ±13 章），后半是条目实际跨度——6 章的小说也显示 1–26，「共 1 - 1 章」读起来像打错字。**建议**：把窗口与数据跨度分开表述（如「视图 1–26 章」「条目覆盖第 1 章」），单章时显示「第 1 章」而非「1 - 1 章」。

**B5 🟡 数量文案空格不统一**：「角色 2 人」「共 1 部作品」有空格，「地点1 处」「读者视角1 条」「创作偏好2 条」「弧线节点1 个」「伏笔与指令1 条」无空格——同一格式的计数在不同视图写法不一致。

### C. 无障碍

**C1 🟠 多处 icon-only 按钮无可用名**：弧线/时间线/读者视角卡片的「✓」（完成）按钮（如 `TimelineView.tsx` 中的 `✓` 文本按钮）、搜索框旁的图标按钮（走查中可访问名为空）、角色/地点卡片与侧栏的「删除」按钮只有「删除」二字（同一列表里两个「删除」无法区分删的是谁）。对比之下章节行的按钮带「编辑章节 雨夜线索」「删除章节 雨夜线索」、素材库参考书按钮带「选择《全局雨夜参考》」——**模板其实已有好范例，CRUD 视图没沿用**。

**C2 🟡 素材库侧栏无图标的「筛选参考书籍」输入框有标签，但搜索/角色/地点等视图的搜索框标签为占位符**：角色搜索框无关联 `<label>`（`CharacterListView` 中 `placeholder="搜索角色..."`），读屏用户拿不到字段名。**建议**：所有搜索框统一 `aria-label`。

### D. 界面美观评审

**浅色主题（默认）**：鼠尾草绿 + 奶油的暖色系（标题栏/活动栏 `#e2e8df` 系、二级面板 `#e8ecd9`、主内容 `#f9f7e8`、对话面板 `#e2e8df`），配色完整统一、无刺眼色块；卡片圆角、阴影、间距一致；封面默认占位图（水墨山水）观感好；状态徽标（绿=就绪、红=失败、黄=提示）语义清晰。主按钮深绿、发送按钮橙色圆钮，强调点克制。整体接近「纸质书 + 台灯」的氛围，对长时写作友好。

**深色主题**：炭灰底（`#141414`/`#1f1f1f`）+ 蓝色选中强调 + 橙色发送键，自洽但没有延续浅色主题的绿色气质——两套主题像是两套皮肤而非同一设计语言的明暗变体（对照 `docs/frontend/theme-design.md` 确认设计意图）。深色下活动栏图标与背景对比尚可。

**可改进处**：
- 活动栏只有图标无文字提示（hover 有 title），13 个图标对新用户是「猜谜」；建议至少给前几个高频项加文字标签或悬浮 tooltip 常驻。
- 图标为细线稿，浅色背景下白/灰描边对比度一般，选中态只有一条竖线，不够醒目（可用填充态或高对比色改进）。
- 帮助/个人中心/素材库等对话框与主视图的风格基本统一，但原生 `confirm()`（A5）是唯一的风格破绽。
- 整体 8–9/10：**美观是当前产品最强的维度**，主要扣分来自术语中英混排（B1/B2）而非视觉本身。

## 四、改进计划

排序原则：先修「用户会误读、误操作」的，再修「用户会困惑」的，最后做打磨。

### 第一批：结构缺陷（🔴/🟠）

| 项 | 改法 | 验收 |
|---|---|---|
| A1 | 书架卡片拆开「打开作品」与「更换封面」，消除嵌套交互 | 可访问性树无嵌套 button；键盘可分别操作 |
| A2 | hover 显隐改为 `group-hover:opacity-100 group-focus-within:opacity-100` | 工作流用 Tab 聚焦断言按钮可见 |
| A3 | 首个章节分块默认展开 + 展开状态持久化（localStorage） | 工作流断言进入作品后第一章列表可见 |
| A4 | 搜索时主区切换为结果视图 | 工作流断言输入关键词后主区出现结果 |
| A5 | 章节删除换应用内确认对话框 | 截图 + 工作流断言 |

### 第二批：术语与文案（🔴/🟠）

| 项 | 改法 | 验收 |
|---|---|---|
| B1 | 新增 taxonomy 中文映射（覆盖度地图/浏览页/候选标签统一走映射） | 截图断言覆盖度地图全中文 |
| B2 | 状态/枚举统一本地化层（含 `run.status`、`known`、`Release endpoint`、`Diff` 等） | grep 复核无裸露英文枚举 |
| B3 | 分隔模板加前缀标签与说明 | 截图 |
| B4 | 时间线标题拆分「视图窗口」与「条目跨度」文案 | 截图断言 6 章小说不显示 1-26 |
| B5 | 统一计数文案格式（补空格） | grep 复核 |

### 第三批：无障碍与打磨（🟠/🟡）

| 项 | 改法 | 验收 |
|---|---|---|
| C1 | 补齐 icon-only 按钮可用名（✓/删除/搜索清空） | 可访问性树断言 |
| C2 | 搜索框统一 `aria-label` | 可访问性树断言 |
| A6 | 评估是否保留活动栏「设置」重复入口（建议移除其一） | 走查确认 |
| A7 | 帮助文案改为引用真实活动栏配置 | 走查确认 |
| 视觉 | 深色主题对齐浅色主题的设计语言（绿色系强调）；活动栏选中态增强 | 截图对比 |

### 不做的事

- 本轮不把素材库 taxonomy 键改为后端返回中文——数据契约保持枚举值不变，只在前端展示层做映射，避免破坏现有契约测试与既有工作流断言。
- 不为 hover 显隐按钮增加常驻可见模式（桌面端 hover 交互可接受，只要键盘聚焦可见即可）。

## 五、评审局限

- 走查基于 mock bridge 与 mock 数据（真实 LLM 行为、导入大文件、真实 Git 仓库均未触发）；凡与真实数据形态相关的怀疑（如 `第{number}章 {title}` 是否为后端真实返回值）已通过源码定位到渲染路径，结论不依赖 mock 特例。
- 截图与快照存在渲染延迟与并发交互干扰（走查期间页面被第三方驱动切换视图），凡涉及具体布局的结论均已回到源码复核。
- 未做真实用户任务测试（F6 在路线图中仍为开放项）；本评审的「用户视角」是结构化的模拟走查，不等同于目标用户的无指导测试。

## 六、结论

一句话：**功能完整、视觉优秀、术语刺眼、细节欠账**。最值得优先投入的是 B1/B2（把素材库和状态文案中文化）与 A1/A2/A3（交互结构与键盘可达性）——前者决定用户「信不信任」素材库，后者决定用户「顺不顺手」用工作台。上述 17 项均为局部改动，无架构性返工，可在三轮内全部收口。
