## 一、问题诊断：复杂度在哪里

- 数据：后端约 11 万行 C#，参考/语料子系统约 6.9 万行（62%）；前端约 3.3 万行，`reference-anchor/` + `reference-use/` 两目录约 1.3 万行（40%）；活动栏 15 个入口。
- 官方口径（tasks.md）：M0–M9 十个里程碑 207 项任务全部 S 级，无一项 P；"系统尚未达到生产完成"；真实用户走查长期开放。
- 历史：v1（reference-anchor）死于"专家级 UI 太重"；v2 用"自动模式 + 专家展开"应对，但底层机器更重。
- 根因："AI 只拼装语料、最大化原句复用"这条公理必然推导出 license/相似度闸门、来源锁定、保真审计、蓝图协调器、50K 调度基建——把单机写作工具做成了语料合规平台。
- 关键认知：**积累不够不是能力不够，是环路太重**。导入→分析→复核→写作正反馈的链条中任何一环太重，积累就断。现有复杂度在抑制积累，而非服务积累。

## 二、产品论点（本次讨论确立）

1. **语料资产**：从参考书籍由 AI 分析提取的多维写作知识，是核心可复用资产。价值在积累（覆盖面 × 确认质量 × 使用反馈），不可跳步重跑。
2. **AI 的缺陷**：不在"写不出"，在细节质感不像人写、宏观设计简陋。对策是**质量迁移**（示范模仿 + 显式工艺约束），不是原文复用（拼装）。
3. **分工**：宏观大纲由作者把控；**AI 只做细化和扩写，细化要参考语料**。AI 不做宏观设计。

## 三、交互模型（唯一主闭环）

```
人提出想法点
  → AI 对话式收集：逐项追问（选择题），收口后问"是否开写？"
  → 作者确认 → 开始写作：
      语料覆盖充分 → 调用语料，细化 + 扩写
      语料不足   → 尝试直写，并明确提示"语料不足"（可引导补充参考书）
  → 人做选择题（beat 选项 / 正文候选 / 处理方式）
  → 往复（选完继续，直到本章完成）
```

访谈收敛规则（已定，作者确认制）：
1. AI 每轮以选择题提问，选项尽量用语料实例；有问题就问，作者答了继续；
2. AI 没有问题可问（或达软性轮数上限）即收口：给出本章计划摘要，问"是否开写？"；
3. 作者确认 → 开写；作者选择补充 → 回到提问；
4. 逃生门：作者任何时刻可主动"开写"，跳过剩余访谈。

计划产物分层（已定，按一般写作逻辑）：

```
大纲（全书）→ 部纲（卷/部）→ 章节细纲（本章 beat）
```

- AI 在每一层都可发起访谈：想法点 → 选择题 → 作者确认。大纲、部纲由**作者把控**（AI 只辅助收集与整理）；**章节细纲是 AI 细化的主战场**——从部纲条目 + 语料场景模式生成细纲草稿，作者选择题确认，确认的就是"是否开写"看到的摘要。
- 写作循环（扩写/候选/往复）消费当前章细纲；一章定稿进入下一章，一层写完进入下一层。
- 存储建议：书目录内 markdown 文件（`大纲.md`、`部纲/第01部.md`、`细纲/第0001章.md`），与章节正文、`novelist.md` 同一范式——作者可在编辑器直接改，git 版本历史自动覆盖，AI 读写与写作上下文统一。现有 `ChapterPlan(novel_id, scope, content)` 单 blob 存储可退役，或降级为聊天侧工作态。

覆盖度信号（已定，<50% 为不足）：
1. 度量单位是**细纲 beat**：对每个 beat 用与写作注入**同一条检索通路**匹配语料，命中即"该 beat 已覆盖"；
2. 覆盖率 = 已覆盖 beat 数 / 细纲总 beat 数（全部命中 = 100%，其余按比例）；
3. **覆盖率 < 50% → "语料不足"**：开写卡片显示覆盖率与未覆盖 beat 清单，作者二选一——直写（诚实标注）或先补语料；
4. 50%–90% → 正常注入，卡片仅提示哪几个 beat 缺语料；
5. 指路补书：按缺失 beat 的场景类型/情绪/桥段说明缺什么，并显示语料库中同类素材目前来自哪本书、建议导入同类型参考书；同一聚合数据也喂给语料区总览的覆盖度地图；
6. 无需新基建：检索、评分、注入是同一条通路，覆盖率只是聚合呈现。

要点：
- **对话优先**：聊天面板是主写作界面；编辑器负责阅读、终稿润色与日常管理。不要求作者先写大纲文档——访谈本身就是大纲采集。
- **选择题原则**：人的一切决策点都以选项呈现（含"都不满意，重来/换方向"），不填表单、不写自由文本（除非作者想写）。
- **语料进入访谈**：追问的选项尽量用参考书实例做素材（"同类冲突，参考书 A 冷处理、B 爆发，走哪种？"），积累越多，问题的选项质量越高。
- **语料覆盖度是一等信号**：按场景类型/情绪/桥段聚合的覆盖率，在聊天里驱动"语料不足"提示，也反向指路"该导入什么书"——覆盖度指标同时服务写作与积累。
- **直写是合法路径**：语料不够时 AI 直写（诚实标注），不阻塞写作。语料是质量杠杆，不是枷锁。

语料系统退到幕后：导入零仪式、后台分析、卡片化复核、写作时自动召回注入、**用后可见**（本章用了哪几条语料、来自哪本书）。

## 四、资产规划

| 层 | 维度 | 服务 | 状态 |
|---|---|---|---|
| 句/段级 | 现有 10 family（情绪/感官/节奏/句法/动作/人物互动/视角/修辞/商业钩子/叙事功能）+ 技法标本 | 扩写 | 保留 |
| 场景级 | 新增 2 个 family：`scene`（场景结构）、`trope`（桥段模式） | 细化 | 枚举词汇沿用内置技能（见下） |

场景级 schema 草案（实施时按此起步，枚举可经复核选择题生长）：

- **`scene`（场景结构，分析单位：Scene 节点）**
  - 场景目标：推进主线 / 塑造角色 / 铺垫 / 兑现 / 揭示信息 / 情感升温 / 过渡缓冲
  - 冲突来源：外部威胁 / 人际对抗 / 内心挣扎 / 误会 / 环境阻碍 / 无冲突
  - 转折：数量（无/单/双/多）× 类型（反转/升级/揭示/打断/新变量入场）
  - 场景结果：达成 / 受挫 / 代价换取 / 引出新问题
  - 入景：对话 / 动作 / 环境 / 内心 / 承接上文；出景钩子：悬念 / 威胁 / 揭示 / 情绪余韵 / 平静收束
  - 节奏：极快 / 快 / 中 / 慢
  - 枚举词汇直接对应内置技能 `scene-beats`（三种入景、三类转折、出口钩子、Try-Fail 节拍）
- **`trope`（桥段模式，分析单位：Scene 节点）**
  - 桥段族：受控词表，种子 20–30 个（打脸 / 退婚 / 扮猪吃虎 / 绝地反杀 / 身份揭露 / 误会解除 / 夺宝 / 比斗 / 营救 / 追逃 / 拍卖 / 秘境探险……）
  - 阶段：铺垫 / 触发 / 发展 / 高潮 / 余波
  - 情绪兑现：爽感 / 紧张 / 悲 / 暖 / 期待 / 愤怒 / 悬疑
  - 演绎方式：标准演绎 / 变奏 / 反套路

两层资产，互补不重复：
- **行为层（技能）**：方法论文档，"怎么想"。内置 scene-beats / plot-hook / pacing-control 等保留，继续作为 AI 行为指引，**同时是场景级 family 枚举词汇的直接来源**（Scene/Sequel、三种入景：动作/反常细节/矛盾状态、三类转折：认知改变/优势逆转/不可回头、出口钩子、Try-Fail 节拍）。
- **内容层（语料）**：案例记录，"实际怎么写的"。结构化枚举、evidence 锚定、可检索/聚合/算覆盖度。细化时两层一起注入：方法论给判断框架，案例给选项与出处。
- **退役**：叙事模式抽取、风格技能抽取（从自己章节/手动样例生成 Markdown 技能的路线——产物不可检索、不可聚合、无 evidence，被结构化语料取代）；风格素材库并入语料导入通道。
| 卷/线级 | —（"行/纲"） | — | **不做**：宏观归作者，AI 不消费 |

- Schema 演进走 additive migration，旧观察原地保值；新增维度只补分析，不重跑全部。
- 资产可携带：语料包导出/导入（原文 + 维度 + evidence + 复核状态），不锁死在与 run/lease 表纠缠的 SQLite。

## 六、积累导向设计

1. 导入零仪式：拖入即后台分析，完成通知，不进工作台。
2. 复核卡片化：原文 + 维度判断，单键确认/驳回；允许抽样复核控质量。
3. 成长可感知：资产视图（N 本书 / M 观察 / K 确认标本）；写作时展示本章消费的语料清单。
4. 成本可见：每本书分析成本/时长指标——积累被预算节流，单价低才跑得勤。
5. 默认体验只保留：书架 / 章节 / 编辑器 / 细化扩写入口 / 语料幕后状态；其余入口收进"高级"。

## 七、验证标准

- 积累里程碑：5–10 本参考书全量分析 + 核心观察确认完毕。
- 消费 A/B：真实章节写作，带语料召回 vs 不带，对比细节质感（作者评分，可加盲评）。
- 通过 → 继续积累；不通过 → 先调 schema/检索，再堆量。
