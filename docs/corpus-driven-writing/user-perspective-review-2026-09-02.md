# 使用者视角评审与改进计划（2026-09-02）

> 评审视角：以「用 AI 细化扩写、以参考书积累质感」的写作者为使用者画像，沿三条日常动线走查——**写一章**（开章→看覆盖→访谈→开写→选择题→用量）、**积累语料**（导入参考书→分析→复核）、**查证与搬家**（浏览检索/语料包）。
> 评审基准：`lightweight-refocus-proposal-2026-08-31.md` 的产品承诺（§3 交互模型、§6 积累导向设计、§8 信息架构）+ 当前实现代码走查。行号以 8ecc1b1 为基线。
> 与既有评审的关系：`robustness-review-2026-09-02(-fixes).md` 解决"出错时系统能否存活"，本文回答"不出错时作者用得顺不顺、功能齐不齐"；`usability-review-2026-07-27.md` 针对已退役的旧工作台，其中 UX-1/2/3 经核实**仍存在于现组件**（见 U6）。

## 一、总评

核心闭环的"骨架体验"已经立住：聊天即写作主界面、选择题卡片、语料自动注入与用量可见、覆盖度三态横幅（本轮健壮性修复后含失败重试）。但站在使用者角度，当前最大的问题不是"功能错"，而是**动线断裂**：

1. **写一章的前提（细纲）藏在「时间线」面板里**——聊天注入与覆盖度信号都依赖 `scope=next` 的章节计划，但全应用唯一的细纲编辑入口是时间线视图的「下一章/近期/远期」tab（`TimelineView.tsx:77,227-241,461-469`）。没有细纲时覆盖横幅静默不出现（`ChatPanel.tsx:1290` `total_count>0` 才渲染），作者不知道"为什么没有语料信号"，更不知道要去哪建。
2. **聊天不知道自己在为第几章写作**——章号由内容区当前 tab 隐式推导（`WorkspaceView.tsx:356-359`），ChatPanel 无任何"当前第 N 章"指示；切到 `novelist.md` 或大纲 tab，注入静默失效，作者不可感知、不可控制。
3. **积累动线是六步显式向导，与"导入零仪式"承诺相反**——填书名选文件→注册→选书→同步等 LLM 分析→确认边界→启动材料化（`ReferenceBookSidebar.tsx:157-198` + `ReferenceCorpusWorkspace.tsx` 全程）；方案 §6.1 承诺"拖入即后台分析，完成通知，不进工作台"。

## 二、使用便利性（U）

### U1 细纲入口与写作闭环割裂 🔴

- **现象**：细纲唯一编辑入口在时间线面板；聊天区无任何入口或引导。无细纲/空细纲时覆盖度返回 `total_count=0`，横幅不渲染——三种状态（没细纲/有细纲无命中/加载失败）在旧版不可区分，本轮修复后失败态已可见，但"没细纲"仍是无提示的空白。
- **影响**：核心信号（覆盖度）与核心动作（注入）对新书用户双双静默失效；时间线面板名为"时间线"，作者不会想到章节计划在里面。
- **建议**：① 覆盖度横幅增加"未建细纲"空态：显示"本章还没有细纲——创建后 AI 将按细纲检索语料"，附「去创建」按钮（跳转时间线计划区或在聊天内联编辑）；② 聊天注入已依赖同一计划，AI 侧 `update_chapter_plan` 工具已存在，可在访谈中由 AI 主动起草细纲（方案 §3 已授权 AI 细化细纲），前端在用量卡旁展示"细纲来源"。

### U2 当前章号不可见、不可控 🔴

- **现象**：`ChatInput.tsx` 无章号指示；`chapterNumber` 只随 tab 路径 `chapters/N.md` 隐式变化（`WorkspaceView.tsx:356-359`）。切到故事状态/大纲/技能 tab → `chapterNumber=null` → 无注入无覆盖，无任何提示。
- **影响**：作者在多 tab 切换的日常操作中会无意识地失去语料注入；"为第几章写"这一核心语境全靠猜。
- **建议**：① ChatInput 上方加章号徽章「第 3 章 · 语料注入开启/关闭」，点击可手动指定/锁定章号（解除与 tab 的隐式绑定）；② 失去章号时（tab 切走）徽章变为「未绑定章节」而非静默消失；③ 徽章状态进入 `verifyCorpusChatWorkflow` 断言。

### U3 帮助文档零覆盖新工作流 🟠

- **现象**：`HelpDialog.tsx`（669 行）grep 不到「语料/访谈/细纲/选择题/覆盖」任何一个词；工具清单仍是旧口径。
- **影响**：访谈收敛规则、选择题原则、覆盖度信号、直写合法路径——这些需要作者配合的交互契约完全靠作者自行摸索。
- **建议**：帮助补「语料写作工作流」一章（想法→访谈→选择题→开写→用量），并把覆盖度阈值（<50% 不足）与 40 beat 上限等规则写明。

### U4 覆盖度"指路补书"承诺未兑现 🟠

- **现象**：横幅只列前 3 个未覆盖 beat（`ChatPanel.tsx:1302-1307`），指引是通用文案"到语料区导入同类参考书"；方案 §3.5 承诺"按缺失 beat 的场景类型/情绪/桥段说明缺什么，并显示同类素材目前来自哪本书"。
- **影响**：作者知道缺语料，但不知道缺**哪种**、该导入**什么书**——积累方向的指路断线。
- **建议**：后端覆盖度 payload 已拿到每个 beat 的命中锚点；扩展为「未覆盖 beat × 已有同维度素材来源书」的聚合（复用 `GetReferenceMaterialCoverage` 的 facet 数据即可起步），横幅显示"缺失：冲突爆发类 3 beat · 同类素材现有《X》《Y》"。

### U5 导入对照"零仪式"承诺是六步向导 🟠

- **现象**：注册（表单+文件选择器）→ 选书 → 「自动分析前 50K」（**同步阻塞等待 LLM**）→ 确认边界 → 启动材料化 → 复核。无拖拽；分析期间不能切页（切页状态丢失，profile 是组件 state，`ReferenceCorpusWorkspace.tsx:87`）。
- **影响**：导入一本书的心理成本高，抑制积累——这正是方案诊断的"环路太重断积累"的残余形态。
- **建议**（分步降摩擦）：① 短期：注册成功后自动选中并滚动到切分步骤（省一步）；「自动分析」改为后台 run 化 + 完成通知（复用材料化 run 的排队基建），页面可切走；② 中期：书架/语料区支持拖拽 `.txt/.md` 文件直接注册；③ 分析与确认合并为"分析→展示边界→一键确认"两步（确认按钮自动出现，无结果时提供手动模板兜底）。

### U6 错误处理硬编码回潮 + 无重试入口 🟠

- **现象**：旧评审 UX-1/UX-2 在现组件**未修**：`ReferenceBookSidebar.tsx:169,177,197,206` 与 `ReferenceCorpusWorkspace.tsx:216,234,253,271,292` 的 catch 均无绑定、硬编码中文，丢弃 `BridgeError.code`（唯一例外是切分分析——本轮 P0-2 修复后 `chapterSplitErrorMessage` 才真正生效）；错误条均为纯文本无重试按钮。注册元数据硬编码（UX-3）也在：`license_status: 'user_provided'`、`visibility: 'private'`、`user_tags: []`（`ReferenceBookSidebar.tsx:182-187`）。
- **影响**：后端精心分类的错误码（来源变更/模型未配/文件超限）到不了作者眼前；失败后要靠重新走流程恢复。
- **建议**：按 `TimelineView` 已有的 `buildVisibleError` 模式（读 code、带诊断、带重试）统一两个组件；错误条统一为可重试组件；注册表单补 license/标签字段或书详情页支持事后编辑（`UpdateReferenceAnchorMetadata` 后端已就绪）。

## 三、可操作性（O）

### O1 访谈无"直接开写"逃生门按钮 🟠

- **现象**：方案 §3 逃生门"作者任何时刻可主动开写"只能靠自由输入文字实现；聊天 UI 没有显式按钮。AI 是否守规矩（每轮一问、适时收口问"是否开写"）完全由提示词约束，作者遇到不收口/连珠炮式提问时没有一键纠偏。
- **建议**：聊天工具栏加「直接开写」按钮（发送固定指令让 AI 立即按当前细纲出正文候选）；配合 ChoiceBlock 的"都不满意，换个方向"形成完整控制面。这符合方案"选择题原则：人的一切决策点都以选项呈现"。

### O2 注入来源不可控 🟡

- **现象**：注入检索 `AnchorIds: []` 全库检索（`FileSystemChatSessionService.cs` 注入构建），作者不能说"这一章只参考《X》"。
- **建议**：ChatControls 或覆盖度横幅加「本章参考范围」（全部/指定书）；`SearchReferenceMaterialsPayload.AnchorIds` 契约已支持，只需 UI 与注入参数打通。低频但高价值（写特殊风格章节时）。

### O3 复核卡缺证据原文对照、无批量/抽样 🟡

- **现象**：复核卡只有 `text_preview` + tags + reason_codes（`ReferenceCorpusWorkspace.tsx:552-568`）；candidate 的 `source_spans`（含 node 定位）契约里有但 UI 未展示；方案 §6.2 承诺"原文 + 维度判断，单键确认"，且"允许抽样复核控质量"无入口。
- **建议**：复核卡加「查看原文」展开（source_span → 章节内定位，复用浏览视图的证据展开模式）；复核列表加"只看待复核前 N 条"的抽样开关；键盘 J/K 或连续确认流。

### O4 浏览视图无自由搜索、无原文定位 🟡

- **现象**：浏览仅支持 按书下拉 + 维度下拉 筛选（`CorpusAreaView.tsx:277-322`），无文本搜索框；观察卡展开只有 `evidence_preview` 文本，无跳转到原文位置。
- **建议**：观察列表后端若支持 `feature_key`/`review_state` 过滤（`ObservationFilterKeys` 已含），前端补搜索输入与更多筛选；证据展开加"在原文中查看"（node → 参考书文本树定位，已有 `GetReferenceCorpusNodeWindow` 契约可直接用）。

### O5 材料化失败提示无修复跳转 🟡

- **现象**：「启动材料化」失败提示"大模型、向量模型和索引均必须可用；修复后请显式重试"（`ReferenceCorpusWorkspace.tsx:254`），但不提供跳转到设置的入口；作者需要自己找到设置对话框→模型页。
- **建议**：错误条加「去配置模型」按钮直达 SettingsDialog 的 model tab（对话框组件已支持 `initialTab`）。

### O6 后台材料化完成无全局通知 🟡

- **现象**：run 进度只在制作页可见（3s 轮询 `ReferenceCorpusWorkspace.tsx:174-180`）；切到写作区后完成/失败无通知。完成回调 `onMaterializationChange` 只刷新本区数据。
- **建议**：run 完成发全局 toast/状态栏通知（含失败原因与「查看」跳回制作页）；与 U5 的后台化配套。

## 五、改进计划

按"先打通动线感知、再降积累摩擦、后补完整性承诺"排序；每批给出验收口径（对齐 AGENTS.md：UI 改动需 build/lint/工作流/截图）。

### 第一批：核心动线感知（纯前端小改，1–2 天量级）

| 项 | 改法 | 验收 |
|---|---|---|
| U2 | ChatInput 章号徽章（第 N 章/未绑定），支持点击锁定 | `verifyCorpusChatWorkflow` 断言徽章三态（绑定/未绑定/锁定）+ 截图 |
| U1 | 覆盖横幅"未建细纲"空态 + 「去创建」入口 | 工作流新书场景断言空态文案与跳转 |
| O1 | 聊天工具栏「直接开写」按钮 | 工作流断言点击后 Chat 调用携带开写指令 |
| U3 | 帮助补「语料写作工作流」一章 | 人工走查帮助内容覆盖访谈/选择/覆盖/直写 |
| U6-轻 | 两个参考书组件的错误条统一加「重试」按钮（错误码透传可顺带 TimelineView 模式） | `test:reference-workspace` 失败注入断言 |

### 第二批：积累动线减负（前后端配合，本迭代）

| 项 | 改法 | 验收 |
|---|---|---|
| U5①/O6 | 切分分析后台 run 化 + 全局完成通知；注册后自动进入切分步骤 | 集成测试：分析进行中可查询状态；工作流断言通知出现 |
| U5② | 书架/语料区拖拽导入（.txt/.md → 注册表单预填） | 工作流拖拽场景 + SafePath 拒绝非法路径断言 |
| F4 | run 完成面板补 tokens/时长（job store 聚合到 run） | 集成测试断言成本字段出站 |
| U4 | 未覆盖 beat 按维度聚合 + 同类来源书提示（复用 coverage facets） | 覆盖度测试补聚合断言；横幅截图 |
| O5 | 材料化失败提示加「去配置模型」直达 | 工作流断言跳转打开 model tab |

### 第三批：完整性承诺（跨迭代，对齐 proposal 落地顺序）

1. **F1 计划产物 markdown 化**（大纲.md/部纲/细纲/第 N 章.md）——迁移 copy-first + 旧 blob 只读兼容一个版本；命名统一为方案口径（大纲/部纲/细纲），时间线面板的计划区随之退役或改为只读视图。
2. **F2 scene/trope 场景级 family**——schema additive migration + 词表种子 + 复核选择题归类生长（依赖 F1 的细纲 beat 作为消费方）。
3. **O3/O4 复核与浏览的证据链**——source_span 原文定位（`GetReferenceCorpusNodeWindow` 已有契约）、观察自由搜索、抽样复核。
4. **F5 语料包 JSONL 通道**——格式（原文引用+维度+evidence+复核状态）、SafePath 导入校验、总览页资产卡片联动。
5. **F3 阈值校准与 F6 真实验证**——积累 5–10 本后按 §7 执行；先埋命中分数分布观测。

### 不做的事（明确出界）

- 不扩大专家控制面（AGENTS.md 红线）：O2 注入范围限定做成轻量徽章弹出，不做多选高级面板。
- 不为 U5 引入"全自动无人确认材料化"——章节边界确认保留人工关卡（切分错误的下游成本远高于一次确认）。

## 六、值得保持

- 聊天三态覆盖横幅（含失败重试）与用量卡/历史重放——本轮健壮性修复的成果，动线感知的正确形态。
- 制作页两段式编号向导（1.章节切分/2.材料化进度）步骤清晰，错误显示 error_code。
- ChoiceBlock 键盘可达、CorpusBrowse 游标分页、总览骨架态（"—"占位）。
- `buildVisibleError`（TimelineView）已是错误呈现的正确范式，值得推广而非重造。
